3. SQLite Architecture & Reactive State Management

SpendWise utilizes a repository architecture decoupled across three primary tiers: UI Presentation, Reactive State Management, and Local SQLite Storage.

State synchronization is powered by TransactionController, a zero-dependency singleton extending standard Flutter ChangeNotifier. When any write occurs, the controller re-executes SQLite aggregations and issues notifyListeners(), causing screens to rebuild instantaneously via ListenableBuilder.

4. Form Validation & Fintech Precision Standard

To eliminate binary floating-point rounding errors common in financial applications, SpendWise enforces the Minor Currency Units Standard:

  • All currency amounts are stored strictly as 64-bit integers representing paisas ($1\text{ PKR} = 100\text{ Paisas}$).
  • An entry of PKR 3,500.50 is parsed and stored as 350050.
  • All SQLite aggregate operations (SUM(amount)) perform exact integer arithmetic with zero precision loss.

7. Challenges Encountered & Senior Engineering Solutions

1. Test Isolation in SQLite FFI Unit Tests
Challenge: Running sequential tests with shared in-memory database paths caused state leakage where transactions created in earlier tests polluted subsequent tests.
Solution: Refactored test/database_test.dart to generate a unique database file path per test using timestamped microseconds (test_db_${DateTime.now().microsecondsSinceEpoch}.db), opening fresh connections in setUp() and cleaning up files in tearDown().
2. FakeAsync Zone Boundary in Widget Tests
Challenge: Flutter widget tests run inside fakeAsync. Calling asynchronous background FFI isolates caused pumpAndSettle() to advance virtual clock time by 10 minutes almost instantly, before the native background isolate delivered its message port response.
Solution: Designed FakeDatabaseService extends DatabaseService, an in-memory repository implementing the exact repository interface for widget tests. This allowed widget tests to verify form validation, interactive creation, edit mode, delete dialogs, and UI rebuilds instantly in-memory, while test/database_test.dart verified 100% of real native SQLite queries independently.
3. Floating SnackBar Feedback Queuing
Challenge: Rapid create, edit, and delete operations queued multiple SnackBars behind Flutter's 4-second default timer, causing noticeable feedback lag.
Solution: Added ScaffoldMessenger.of(context).clearSnackBars() prior to displaying each new confirmation, ensuring user feedback is delivered immediately.

8. Key Engineering Learnings

  • Fintech Mathematical Precision: Utilizing minor currency units (paisas) standardizes database persistence and ensures zero precision loss in aggregate SQL calculations.
  • Separation of Concerns in Repositories: Decoupling database queries from state controllers enables clean mockability, high test execution speed, and maintainable application code.
  • Zero-Dependency Flutter Reactive State: Leveraging ChangeNotifier and ListenableBuilder yields a responsive, clean architecture without heavy third-party state management libraries.
